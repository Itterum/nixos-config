# Minimal Niri desktop design

Date: 2026-08-28

## Goal

Replace DankMaterialShell and its greeter with a small, declarative desktop
stack built from greetd, tuigreet, Niri, Fuzzel, Mako, swayidle and swaylock.
Keep the existing Catppuccin Mocha appearance, Papirus-Dark icons and macOS
cursor without a dynamic theme daemon.

## System session

`modules/desktop/session.nix` owns login and session-level integration.
greetd runs tuigreet on VT1 as a text greeter. Tuigreet remembers the last user
and starts `niri-session` directly. Niri remains the only graphical session and
continues to supply the Wayland session, portal and swaylock PAM integration.

The workstation profile imports the new session module instead of the DMS
module. `programs.dms-shell` and `services.displayManager.dms-greeter` remain at
their disabled defaults. The experimental personal Quickshell files are kept
in the repository but are no longer imported by Home Manager.

## User services and applications

Home Manager owns four focused components:

- Fuzzel is installed but runs only when invoked with `Mod+Space`.
- Mako is the FreeDesktop notification daemon and uses a static Catppuccin
  Mocha palette.
- swayidle runs in the Niri graphical session. It locks after five minutes,
  powers monitors off after ten minutes, and locks before sleep. On the laptop
  only, it suspends after thirty minutes; the desktop never auto-suspends.
- swaylock provides the lock UI and uses the same static palette.

Media-key helpers are regular command-line packages rather than background
services: WirePlumber's `wpctl` controls audio, `brightnessctl` controls display
brightness, and `playerctl` controls MPRIS players.

## Static appearance

`home/itterum/desktop.nix` defines the shared Catppuccin Mocha colors once and
reuses them for Fuzzel, Mako and swaylock. GTK uses Catppuccin Mocha Mauve,
Papirus-Dark icons and the macOS cursor. Qt uses qt5ct/qt6ct, the Kvantum
Catppuccin Mocha Mauve theme and Papirus-Dark icons.

No service derives colors from the wallpaper and no runtime theme switcher is
installed. A later theme change is made in Nix and applied through a rebuild.

## Niri ownership

The checked-in `home/itterum/files/niri/config.kdl` becomes self-contained.
It must not include files generated by DMS. The current static two-monitor
layout, cursor, gaps, window-management bindings, screenshots, audio keys,
brightness keys and MPRIS keys are preserved.

Niri adds the Omarchy-inspired visual layer itself: a Mocha background, an
active mauve focus ring, ten-pixel window corners and soft shadows. Fuzzel,
Mako and swaylock provide their own matching surfaces.

## Safety and migration

The change does not run `nixos-rebuild switch`, restart greetd, terminate the
current DMS process or modify the live home directory. It only changes the
declarative configuration. Existing unrelated and uncommitted Helix, Zed and
Quickshell work is preserved.

## Verification

Repository regression checks assert that DMS and its greeter are disabled,
greetd uses tuigreet to start Niri, the four Home Manager components are
enabled, the icon and cursor themes are correct, and the Niri source contains
no DMS includes. Both host configurations must evaluate and build.
